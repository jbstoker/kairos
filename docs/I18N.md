# Translations (i18n)

Kairos ships with seven languages: **English (default), Dutch, Frisian,
German, French, Spanish and Chinese (simplified)**.

- **CLI**: `kairos --lang=nl` (also `--lang=de`, `--lang=zh`, …). `--help` is
  shown in the requested language too.
- **Web app**: the switch lives in the **⚙️ Configure** tab → "🌐 Language".
  Your choice is stored in `localStorage` (`kairos_lang`) and re-applied on
  every visit; offline and PWA-installed use included.

## How it works

| Layer        | File              | Holds                                              |
|--------------|-------------------|----------------------------------------------------|
| Python / CLI | `core/i18n.py`    | CLI strings, canonical Kairos names, checksum text |
| Web / PWA    | `web/i18n.js`     | UI strings, help content, canonical names          |

Both are **one flat `key -> text` table per language** with English as the
source of truth. Display code only ever holds *canonical English keys*
(e.g. `"Harvest Moon"`, `"Spring"`); translation happens at render time, so
stored observations and data files stay language-neutral.

## Adding a language

1. **Python** (`core/i18n.py`): copy the `"en": { ... }` block, rename the key,
   translate the values, and add the code to `LANGUAGES` + `LANG_NAMES`.
2. **Web** (`web/i18n.js`): same — copy the `'en': { ... }` block into
   `CATALOG`, translate, and add the code to `LANGS` + `LANG_NAMES`.
3. Run the parity tests — they fail if your new block misses a key:

   ```bash
   pytest tests/test_i18n.py tests/test_i18n_web.py
   ```

## Canonical names vs. proper nouns

The day/week/month/season/archetype names of the Kairos calendar itself are
translated (e.g. `Harvest Moon → Oogstmaan`). Tradition-specific proper nouns
such as `Solaris` or `Zhengyue` are left untouched — `tr_name()` returns the
original name when no translation exists.

## Notes / known scope

- The PWA web manifest (`web/site.webmanifest`) description is static and not
  localised (browsers don't localise installed app metadata).
- The `data-i18n` HTML attributes cover the interface; long-form help content
  (meanings, planet notes) is translated through `web/i18n.js` keys.
- The language `<select>` is populated by `web/i18n.js` (`#languageSelect`);
  it is intentionally in the Configure tab, next to the tradition picker.
